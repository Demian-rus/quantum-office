# BANK-03.1 — годы актуальности экзаменационных заданий

База: принятый EXAM-01 `c1a627064a40da66f91c602ffa76149814a4100a`. Зависимый Draft PR #163.

## Модель и совместимость

`year` — год происхождения материала (строка); `examYears` — независимое поле записи банка с целыми годами 1900–2099. При записи список сортируется, повторения удаляются. Отсутствие поля у старой записи равнозначно пустому списку, но не приводит к перезаписи записи. Для обычной практики непустые годы запрещены. Поддержаны текущие ОГЭ и ЕГЭ; автоматических назначений нет. При изменении экзамена требуется подтверждение сброса; последующие годы назначаются явно. QWORK v1 получает опциональный `examYear` для выбранной модели, без влияния на заголовок и номер варианта.

SQLite schema 1 сохраняется. По первому нагрузочному прогону (10k: открытие 476,3 мс против 279,9 мс) IndexedDB повышается до v3 исключительно для транзакционного multiEntry-индекса `examYears`; записи, номера, ревизии и вложения не переписываются. IDB читает конкретный год по новому индексу, категории годов — по уникальным ключам индекса, «без подтверждения» — курсором по метаданным; принадлежность году проверяется до пагинации. Вложения не гидратируются при просмотре каталога/выборе целей. SQLite применяет `json_each` к JSON body и обычные индексы остальных фильтров до COUNT/LIMIT/OFFSET. Для годов нет отдельной таблицы, требующей синхронизации. Эффективность проверяется на 1k/5k/10k.

## Интерфейс

Фильтр «Год актуальности» независим от года происхождения, допускает все, конкретный год и отсутствие подтверждённых годов. Теги отображаются в списке и карточке, но не печатаются. В редакторе произвольный год и быстрые кнопки соседних годов; удаление тега или очистка всех; штатное сохранение и защита несохранённых изменений.

Выделение страницы и всех результатов — разные команды; для всех результатов подтверждается точное число. Массовое действие добавляет, удаляет или заменяет указанный набор годов (замена отдельно подтверждается). Репозиторий принимает ID и ожидаемые ревизии в одной транзакции; меняются только годы, ревизия и время изменения. Повторное назначение не переписывает запись. При конфликте откатывается весь набор. Ограничение QWORK в 80 задач сохраняется отдельно от выделения в каталоге.

Сборка проверяет выбранные записи по актуальным данным хранилища и ещё раз по снимку ID/ревизий перед добавлением. Смена фильтра во время операции отменяет сборку. При выбранном году нельзя смешивать типы экзамена; неподходящие записи не исключаются молча. При добавлении к работе требуется соответствующая модель, либо пустая работа.

## Обмен и резервные копии

QWBANK v1/v2 включают назначенные годы. Контрольная сумма v2 проверяется до нормализации. Сигнатура дедупликации исключает только новый редактируемый набор годов (помимо прежних allocation-метаданных); остальной полный состав задания участвует в сравнении. Совпадающее задание с другими годами пропускается, результат сообщает `yearConflicts`, локальные теги сохраняются. Для SQLite прежние сигнатуры совместимы и не пересчитываются при массовом изменении годов. QWBANK v3 сохраняет точные записи, ID, номера, ревизии и активы; старые архивы проверяются по исходному SHA-256 без материализации отсутствующего поля.
