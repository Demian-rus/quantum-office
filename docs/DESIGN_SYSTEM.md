# Quantum Office — дизайн-система

TASK 096. База: TASK 095, `6927b7b6918f3f25365e383604c0ffb092aa6afc`.

## Структура

`src/styles.css` — только манифест локальных импортов. Сборщик рекурсивно включает их в единственный автономный HTML. Порядок и назначение модулей:

| Файл | Ответственность |
| --- | --- |
| `foundation.css` | Палитры, семантические роли, типографическая база, интервалы, размеры, тени, слои, движение |
| `components.css` | Сброс, обзор, карточки, общие меню оформления и справки |
| `shell.css` | Единственная общая шапка, навигация, заголовок и действия документа |
| `sheets.css` | Компактная лента, виртуальная сетка, меню, инспекторы и печать Sheets |
| `writer-slides.css` | Ленты Writer/Slides, лист, сцена, миниатюры и свойства |
| `studio.css` | Навигация, библиотека, сцена, слои и инспектор Studio |
| `controls.css` | Общие интерактивные цвета и состояния; геометрия остаётся у компонента |

Правила адаптации находятся рядом с владельцем компонента. В Foundation нет селекторов конкретных редакторов. В остальных модулях нет исключений `html[data-qo-theme=dark]`: тема задаёт значения ролей, компонент работает с любой палитрой.

При миграции удалены 548 заведомо перекрытых деклараций; одинаковые селекторы в одной области media объединены. Studio и шапка переписаны как самостоятельные владельцы своих стилей. Сохранены геометрия виртуализации, закреплённые слои, ограничения форматирования и стили печати. Это не смена схем документов.

## Цветовые роли

| Роли | Применение |
| --- | --- |
| `--qo-bg` | Пространство вокруг документа/холста |
| `--qo-surface`, `--qo-surface-alt`, `--qo-surface-raised` | Панель, вторичная панель, приподнятая поверхность |
| `--qo-text`, `--qo-muted` | Основной текст и подписи; оба рассчитаны для чтения |
| `--qo-border` | Ненавязчивое декоративное разделение |
| `--qo-border-strong` | Значимая граница поля или управления |
| `--qo-hover`, `--qo-pressed` | Временное наведение и удержание |
| `--qo-accent`, `--qo-accent-soft`, `--qo-selected-hover`, `--qo-accent-border` | Выбранное состояние и его наведение |
| `--qo-accent-fill`, `--qo-accent-fill-hover`, `--qo-accent-fill-pressed`, `--qo-on-accent` | Основное действие и его текст |
| `--qo-focus` | Клавиатурный фокус |
| `--qo-shell*` | Отдельная постоянно тёмная шапка, включая читаемый светлый акцент |
| `--qo-paper-accent` | Рамка выделения на всегда светлом содержимом; не цвет документа |
| `--qo-danger*`, `--qo-warning*`, `--qo-success*` | Семантические сообщения, независимые от выбранного акцента |

Светлая тема — нейтральные прохладные поверхности, мягкие цветные выделения, умеренные тени. Тёмная — отдельная шкала глубины: сцена глубже, панель светлее, меню приподнято тенью. Основной акцент тёмной темы светлее, его заливка имеет тёмный текст. У всех четырёх акцентов свои варианты для каждой темы. Акцент не перекрашивает весь интерфейс.

`--qo-control-ink/accent/active/edge` — совместимые псевдонимы существующих элементов, а не отдельная палитра. Не создавайте новые параллельные наборы цветов.

## Состояния и компоненты

Готовый универсальный элемент: `.qo-control`; основное действие: `.qo-control.qo-control-primary`. Существующие `.tool-btn`, `.qo-work-btn`, `.qs-btn`, `.qs-layer` и другие компактные элементы подключены к той же системе.

1. Default — нейтральная поверхность/прозрачный инструмент.
2. Hover — нейтральная подложка и граница.
3. Selected (`aria-pressed=true`, `aria-selected=true`, `.active`, `.selected`, `.is-active`) — мягкий акцент, акцентный текст и граница.
4. Selected + hover — отдельная, немного усиленная подложка.
5. Pressed (`:active`) — временное удержание, отдельная нейтральная подложка.
6. Disabled — приглушённый нейтральный вид, одинаковый для выбранного и невыбранного элемента. Нативный `disabled` предпочтителен; `aria-disabled` требует блокировки обработчика.
7. `:focus-visible` — кольцо 2 px, сохраняется поверх выбранного состояния. В шапке кольцо светлое.
8. `aria-busy=true` — индикатор занятости без изменения геометрии; reduced motion отключает вращение.

Карточки задают `--qo-control-bg` и `--qo-control-border`, если им нужна постоянная подложка. Они наследуют общие состояния. Не заменяйте фокус на постоянный `:focus` и не отключайте outline глобально.

Меню оформления сохраняет тему/акцент в существующих ключах `quantum-office-theme-v1` и `quantum-office-accent-v1`. Системная тема слушает `matchMedia`. Выбор, Escape и нажатие вне меню закрывают его; Tab циклически перемещается внутри.

## Типографика и плотность

Системный стек Segoe UI / Inter / Arial без загрузки веб-шрифтов. Шапка 40 px, название 11 px, статус 8 px. Панель инструментов Studio 44 px, обычное управление 32 px. Компактные инструменты 23–29 px; подписи 9–11 px. Текст свойств 11–12 px. Рабочая область получает оставшееся пространство.

Базовые интервалы 4/8/12/16/24 px; скругление управления 6 px, всплывающей панели 10 px. Используйте `--qo-space-*`, `--qo-control`, `--qo-radius`, `--qo-shadow`, `--qo-z-panel/menu/dialog`. Избегайте прыжков/масштабирования иконок при наведении. `--qo-motion` уважает reduced motion.

## Содержимое и тема

Цвета содержимого не являются цветами приложения. Не применять общие цветовые селекторы ко всем потомкам редактора.

- Ячейки сохраняют собственные заливки/текст, включая импорт XLSX.
- Лист Writer остаётся белым; его форматирование хранится в QDOC.
- Слайды сохраняют фон, цвета и размеры в QSLIDES. `container-type:inline-size` и `cqw` масштабируют только предпросмотр текста пропорционально сцене, исходный размер остаётся в модели.
- Studio сохраняет пиксели, фон и цвета объектов в QSTUDIO. Миниатюры шаблонов показывают их настоящие цвета. UI выделения не входит в плоский экспорт.
- Печать имеет отдельные правила; тема экрана не должна затемнять страницу.

Допустимые физические цвета вне Foundation: содержимое документов, образцы цветов, миниатюры готовых шаблонов, прозрачная шахматная подложка и демонстрации темы. Новые цвета интерфейса должны идти через семантические роли.

## Адаптация

Шапка — стабильная grid-компоновка с названием между навигацией и действиями. На 1230 px скрывается словесный логотип; на 800 px команды переходят к компактным иконкам с доступными именами и подсказками. Команды сохраняются.

Ленты прокручиваются горизонтально. Сцена Writer прокручивается, миниатюры Slides и свойства имеют независимую прокрутку; на узких экранах свойства Slides переходят вниз. Studio до 1100 px использует выдвижные панели: библиотека открывается слева, свойства справа; открытие одной закрывает другую. Кнопки открытия остаются в верхней панели, все разделы доступны в навигации. На широких экранах обе панели могут быть закреплены одновременно.

Матрица приёмки: 1920/1440/1024/768 px, обе темы, 100/125/150%. В headless Chromium масштаб проверяется равной физической площадью, уменьшением CSS viewport и соответствующим DPR. Это эквивалент проверки компоновки при zoom, а не управление меню масштаба конкретной установленной версии браузера.

## Каталог и проверки

`npm run build` создаёт `dist/components.html` из `docs/components.html` с **теми же** собранными стилями. Работает автономно. Переключает тему/акцент, показывает настоящие кнопки и инструменты, выбранное + недоступное состояние, занятость, поля, чекбокс, ползунок, вкладки, слои, меню и нативный диалог. Экспортирует текущие роли в JSON. Это инструмент проверки, не новый раздел продукта.

`npm run test:design-system` запускает Chromium: вычисленные контрасты, реальные hover/pressed/focus, изоляция моделей, сохранение настроек, 96 компоновок и работа узких панелей. Артефакты — `evidence/task096`. `npm test`, сборка и исторический браузерный CI проверяют функции редакторов. Просмотр снимков обязателен после изменения темы/геометрии; коэффициенты не заменяют оценку композиции.

Ориентир AA: текст 4.5:1, значимые рамки/фокус 3:1. Декоративные разделители и отключённые элементы имеют другое назначение; не усиливайте все границы до одинаковой тяжести. Нельзя объявлять полную доступность продукта только по проверке палитр.

## Добавление компонента

1. Выберите существующий компонент; задайте только нужную геометрию в его модуле.
2. Используйте семантические роли и общие состояния. Для нового вида элемента расширьте семейство в `controls.css`, не копируйте по редакторам.
3. Добавьте реальный пример в каталог, проверьте две темы и четыре акцента, мышь/клавиатуру и узкую ширину.
4. Если меняется сохранение — добавьте round-trip и проверку повреждённого файла.
5. Обновите документацию и приложите осмысленные снимки.

Запрещены: дописывание тематических заплаток в конец монолитного файла; новый `!important` для цвета; исключения тёмной темы по отдельным компонентам; жёстко заданный зелёный для общего состояния; глобальное перекрашивание содержимого; сокрытие единственного пути к команде; перестройка документа при смене темы.
