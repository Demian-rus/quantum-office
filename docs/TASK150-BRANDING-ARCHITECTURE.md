# QX: архитектура оформления экспортов

Инвентаризация исходников TASK150, база main
`d0f1b3c6ec98b88aa73d784f5f5859be8059a338`. Это предложение для TASK151;
изменения экспортёров Writer, Sheets, Slides и диагностики не сделаны.

## Четыре независимых слоя

1. **Документ:** исходные текст, формулы, клетки, SVG-объекты, ответы, ID.
   Экспорт получает валидированный снимок; никаких логотипов в содержимом.
2. **Представление:** размер страницы, поля, пагинация, разрывы, разлиновка,
   резерв под колонтитулы. Каждый редактор сохраняет собственный layout adapter.
3. **Тема:** версионированный `ExportTheme` с идентификатором, шрифтами,
   цветами, знаком, линиями и режимом monochrome. Настройки экспорта хранятся
   отдельно от QWORK/QDOC/QBOOK/QSLIDES. Тема не должна подменять пользовательские
   цвета диаграмм/слайдов; монохромная копия создаётся только по явному выбору.
4. **Метаданные:** `ExportMetadata` — title, subject, creator, producer,
   themeId/themeVersion и suggestedFilename; только поддерживаемые поля формата.
   Метаданные не являются защитой от удаления или доказательством авторства.

Контракт будущего адаптера: `snapshot → render(snapshot, layout, theme) →
validate → serialize(rendered, metadata)`. Снимок сравнивается до/после.
Отдельный capability map определяет допустимые украшения для каждого формата.
Уже в TASK150 `qwPrintTheme(options)` отделён от QWORK v1; никакой темы по
умолчанию нет. API используется только генератором образцов; переключателя
темы в пользовательском интерфейсе пока нет. Полный общий registry и адаптеры
других редакторов — работа TASK151.

## Реальные форматы и пределы применения

| Редактор / существующий экспорт | Визуальное оформление | Идентификация и ограничения |
| --- | --- | --- |
| Работы: Print-to-PDF / печатный HTML | Шрифты, знак, заголовки, линии, колонтитулы; настоящий MathML и SVG | HTML title/meta; PDF creator/title через отдельный поддержанный этап, без raster |
| Работы: QWORK v1; банк QWBANK | Не добавлять знак в задачи/ответы | Имеющиеся format/version и имя файла; новые поля требуют отдельного решения, schema не меняется |
| Writer: HTML и браузерная печать/PDF | Печатная оболочка и отдельный слой темы | Сохранять пользовательские стили и содержимое, проверять собственные колонтитулы |
| Writer: DOCX | Возможны стили, колонтитулы, vector DrawingML/изображение знака | Адаптер `writer-docx.js`, OOXML core/app/custom properties; совместимость частичная, проверить Word/LibreOffice |
| Writer: TXT | Визуального слоя нет | Имя файла; не приписывать бренд в пользовательский текст |
| Writer: QDOC | Тема при отображении возможна, данные не украшать | Имеющийся контейнер/имя файла, без изменения v2 |
| Sheets: печать/PDF | Оболочка страниц, поля/колонтитулы | `planPrint`/`printHTML`; не заменять цвета клеток, диаграмм, формулы |
| Sheets: XLSX | Колонтитулы/параметры печати; отдельный branded-export adapter | OOXML properties; не вставлять строку/лист с логотипом, не менять значения и стили клеток; XLSX partial |
| Sheets: CSV | Невозможно | Имя файла, опциональный отдельный manifest; не добавлять бренд в строки CSV |
| Sheets: QBOOK / общий QBACKUP | Не вставлять бренд в книгу | Существующие format/version; новые метаданные лишь после согласования схемы |
| Slides: PNG текущего слайда | Знак возможен в отдельном export overlay | Не менять объекты/координаты слайда, не закрывать содержимое; для слайдов без свободного места preview/conflict warning |
| Slides: QSLIDES | Тема только при отображении | Сохранить presentation и объекты; filename/container. Экспорт PPTX отсутствует; отдельного PDF-экспортёра Slides нет |
| Диагностика: учебный HTML, отчёт HTML → print/PDF | Возможна независимая печатная оболочка | Не переносить ответы/данные ученика в учебный лист; не распространять тему на отчёты в TASK150 |
| Диагностика: CSV, QDIAG/QDIAGX, QBANK/QBANKX, QTPL/QTPLX | CSV/JSON/ZIP не имеют печатного слоя | Имя/имеющиеся manifest; схемы и данные не менять |

Источники: `src/main.js` (writer/slides/download/Sheets print actions),
`src/core/{work-builder,work-print,printing,xlsx,xlsx-print,writer-docx,
diagnostics,diagnostic-media}.js`. Скрытая ветка `slides-print` вызывает общий
window.print, но не является готовым специализированным PDF-макетом Slides.
Новые форматы экспорта, PPTX и официальные экзаменационные шаблоны не обещаются.
