# TASK160.1 — универсальная компоновка экзаменационных сборников

База: PR #146 (`fix/task158-shared-spread-header-qx`), Draft PR #147
(`fix/task1601-layout-flow-axes`). Merge в `main` запрещён.

## Исправлено — P0/P1

1. В `booklet` ответы не перекрывают условия и рисунки. По умолчанию они идут
   за полным flow-root; у коротких условий после измерения текстового блока
   могут выравниваться по нижней границе рисунка. При недостатке места —
   автоматический возврат к нормальному потоку.
2. Таблицы, если они представлены HTML-таблицами, идут **после** условия,
   центрируются в текстовой области. Таблицы в виде PNG требуют отдельного
   редактирования исходного изображения. Первоклассного редактируемого
   `table`-объекта в QWORK v1 пока нет.
3. Нижние рисунки центрируются, авторазмещение учитывает ширину и высоту
   пробного текстового блока, шрифты SVG по возможности не уменьшаются.
4. У стрелок координатных осей separate SVG path-треугольники:
   стержень заканчивается у основания наконечника.
5. QX — встроенный рукописный шрифт 15pt, чёрный, без подложки/обводки.
6. Компактная нумерация и печать в A4: portrait или landscape spread
   с двумя независимыми колонками.

## Банк — P2

- `bankNumber`: постоянный **числовой** номер 1–99999 отдельно от внутреннего
  `id` и порядкового номера задания в варианте.
- Для legacy-QWBANK v1 без номера выполняется локальная миграция с выдачей
  уникальных номеров. Конфликты номеров при импорте разрешаются без
  изменения содержимого задания. Уникальность гарантируется в пределах
  текущего объединённого локального банка, не глобально между устройствами.
- Номер участвует в поиске с/без ведущих нулей, виден в карточке банка.
  Уже имеющийся банковский редактор открывает всю запись, включая рисунок,
  ответ и решение.
- При добавлении в вариант `source.number` и `source.slot` сохраняются
  в QWORK v1. Печать: `[7] Тип 7 № 01807` для записи, содержащей такой номер.
- Номер не придумывается для несохранённых в банк заданий.

## Оставшиеся ограничения

1. В QWORK пока нет редактируемых нативных таблиц; правило HTML-таблиц не
   гарантирует корректную геометрию уже растеризованных таблиц.
2. Общие гарантии для любых страниц при всех возможных сочетаниях объектов
   требуют более широкой матрицы автоматического тестирования.
3. Два исторических CI-теста на базовом коммите PR #146 уже имели ошибки:
   TASK150 review и общий browser smoke. Их ошибки и последствия отдельно
   фиксируются в логах; нельзя считать всю CI-матрицу зелёной только по
   текущим TASK160.1 тестам.
