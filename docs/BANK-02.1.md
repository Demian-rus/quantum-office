# BANK-02.1 — визуальный редактор и оформление заданий

Работа продолжает BANK-02 от `a5e4df559065093bb55ec46e2fc671c09add6f50` в ветке `feat/bank-02-task-editor`. За основу экранной типографики взяты гарнитура, компактная нумерация и правила компоновки печатного сборника TASK150–165. Эталон TASK166.4 для сравнения находится в `evidence/task1664-print/ege2018-portrait-browser.pdf`.

## Редактирование

- При открытии задания выбран визуальный режим. Панель форматирования применяется к выделению и абзацам в редакторе. Отдельная команда «Исходный текст» открывает существующее строковое представление. «Предпросмотр» показывает результат для текущей вкладки.
- Формула вставляется через панель. Щелчок по формуле или Enter при фокусе на ней открывает её редактирование. Перед применением виден результат. Ctrl+B, Ctrl+I, Ctrl+U форматируют выделение. Ctrl+Z и Ctrl+Y управляют историей вкладки, Ctrl+S сохраняет задание.
- Копирование между визуальными полями сохраняет поддерживаемое оформление. Вставка из других приложений использует текст. Таблицы редактируются в ячейках. Для нестандартной разметки, перестройки таблиц и ручного редактирования сложных формул доступен исходный текст.
- У учебного текста своя офлайн-гарнитура. Компактный рисунок располагается рядом с условием, широкий рисунок и таблица идут ниже. В тёмной теме программные рисунки используют цвета учебного листа. Встроенные PNG, JPEG и WebP сохраняют собственные цвета. В увеличенном режиме масштабируется весь лист вместе с раскрытым решением. «Белый лист» переключает представление независимо от темы приложения.

QWORK v1 и QWBANK v3 по-прежнему хранят строки с принятым подмножеством Markdown и формул. Рендерер использует MathML, включая дроби, степени, индексы, корни и системы из 2–8 строк. Вложенные списки, свободный импорт форматированного HTML и произвольные пакеты LaTeX выходят за пределы этой модели. В задании одна активная иллюстрация. Графики и схемы редактируются в существующих редакторах. История работает во время текущего сеанса редактирования задания.

## Печать

Для оформленных материалов используйте «Макет и экспорт PDF». Экзаменационный сборник использует белый A4 с одной колонкой в вертикальной ориентации и двумя колонками в горизонтальной. Заголовок стоит на первом листе, подпись QX | Квант Икс — внизу. Постоянные номера присутствуют и в ключе, если исходные задания добавлены из банка. Решения и критерии попадают в ключ по выбору преподавателя. Прямой растровый путь совместимости сообщает, что для оформленных заданий требуется векторный PDF.

## Проверка и примеры

`tests/bank021_browser.cjs` проверяет реальное визуальное редактирование, клавиатуру, составной ввод Chromium, копирование и вставку, переход к графику, повторное открытие с ревизией, совместимость QWORK, отклонение повреждённого QWBANK и восстановление 14 заданий в отдельном профиле. Сценарий сохраняет `study-portrait.pdf`, `study-landscape.pdf`, `study-key.pdf`, `study.qwork` и `study.qwbank` в `evidence/bank-02.1/`. В `screenshots/` находятся сравнения редактора, карточки и увеличенного режима на одинаковых данных, плюс светлая тема, белый лист и пример исходного рисунка в тёмной теме. В `logs/` находятся журналы проверок. Тесты используют временные профили Chromium и синтетические задания.

Прошли 638 тестов JavaScript, сборка HTML/ZIP, браузерные сценарии BANK-01, BANK-02, BANK-02.1, TASK144, TASK156, TASK163–166, TASK166.4 (печать и геометрия) и TASK167.3. Windows x64 собран с Rust 1.100.0. Все 12 Rust-тестов прошли на временных данных. В `pdf-pages/` находятся отрисованные страницы трёх PDF. Проверены размеры A4, порядок постоянных номеров и разделение ученического варианта и ключа. Вручную просмотрены 3 вертикальных листа, 2 горизонтальных листа и 3 страницы ключа.

Для сравнения с базой сохраните исходный HTML командой `cmd /c "git show a5e4df559065093bb55ec46e2fc671c09add6f50:Quantum-Office.html > evidence\bank-02.1\before\Quantum-Office.html"` после создания каталога `before`. Вместо этого можно передать путь к базовому HTML через `QO_BANK021_BASELINE`. Затем выполните `npm test`, `npm run build` и `node tests/bank021_browser.cjs`.

Для личной браузерной приёмки используйте новый профиль по инструкции из [BANK-01.md](BANK-01.md) и восстановите `study.qwbank` через «Файлы и данные» в пустом банке. Для интерактивной приёмки WebView2 нужен отдельный профиль Windows, VM или Windows Sandbox. Тестовый EXE находится в `evidence/bank-02.1/quantum-office.exe`. В PowerShell из корня проекта подготовьте конфигурацию для компьютера, где доступна Windows Sandbox с WebView2.

~~~powershell
& .\scripts\bank02-windows-sandbox.ps1 `
  -Executable .\evidence\bank-02.1\quantum-office.exe `
  -Fixture .\evidence\bank-02.1\study.qwbank
~~~

Откройте выведенный `.wsb` и восстановите `C:\Bank02Input\fixture.qwbank` в гостевом банке. Интерактивная приёмка Windows остаётся открытой.
