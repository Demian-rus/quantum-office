# Quantum Office — TASK166.1: хранилище банка задач (IndexedDB)

## Состояние и назначение

Ветка `feat/task166-durable-bank-storage`, Draft PR #154, база `main` @ `b82a71b907bc9256a26adb559c8c18b9d0573f3d`. Никаких изменений `main` или сторонних веток.

Ранее единый `localStorage['quantum-office.work-bank.v1']` содержал JSON-массив с максимумом 500 задач. Новый источник истины — **одна** IndexedDB-база `quantum-office-bank` версии 1; старый массив остаётся только для недеструктивной миграции/восстановления, не используется для текущих CRUD.

## Схема хранилища

| IndexedDB | Назначение |
| --- | --- |
| `tasks` | One record per task, primary key `id` |
| `tasks.bankNumber` | Уникальный индекс постоянных номеров до 99999 |
| `tasks.subject/grade/exam/year/part/slot/difficulty/type/topic/subtopic/origin` | Индексы по метаданным |
| `tasks.updatedAt` | Индекс последнего изменения |
| `meta.sequence` | Последний выданный номер, включая номера удалённых записей |
| `meta.legacyMigration` | Атомарная отметка о завершённом переносе |
| `meta.legacyBackup` | Оригинальный JSON до миграции + FNV-1a для обнаружения случайного повреждения |

Объект задачи сохраняет QWORK v1 без преобразования текстов, решений, критериев, графиков, SVG-схем и изображения. Поля записи: `id`, `bankNumber`, `task`, метаданные, `type`, `revision`, `createdAt`, `updatedAt`. **Большие Base64-изображения пока хранятся внутри записи**; вынос в отдельное двоичное хранилище с учётом ссылок запланирован на TASK166.3.

## BankRepository

`src/core/bank-repository.js` экспортирует `BankRepository` и фабрику `createBankRepository`. Контракт:

- `open/close`: открытие/закрытие IndexedDB, контроль блокировок и миграции;
- `getTask(id)`: получение отдельной записи;
- `listTasks(filters,{offset,limit})`: индексированный курсор, до 80 записей на страницу;
- `listFacets(fields)`: уникальные значения фильтров через ключи индексов;
- `createTask(task)`: атомарное выделение номера и сохранение в `tasks`/`meta`;
- `updateTask(id,task,revision)`: CAS по версии записи, ошибка `REVISION_CONFLICT`;
- `deleteTask(id,revision?)`: защищённое удаление;
- `importBank(data)` / `exportBank()`: QWBANK v1 и предварительный расширенный обмен v2 для более 500 записей;
- `getStatistics()`: число записей, состояние миграции и оценка origin-хранилища (не отдельный точный размер банка).

Интерфейс `src/core/work-builder.js` использует `qwBankRepository`. Каталог запрашивает **30 записей на страницу**, не создаёт тысячи карточек в DOM. Фильтрация и поиск выполняются в репозитории; поисковый запрос по произвольной подстроке требует прохода по индексированному набору записей. В TASK166.3 можно дополнительно реализовать токенный полнотекстовый индекс для очень больших коллекций.

## Безопасность переноса

1. При первом `open()` анализируется старый QWBANK из `localStorage`, если он есть.
2. Сначала валидируются **все** записи; повреждённые не пропускаются.
3. В одной IndexedDB-транзакции создаются записи, резервный `legacyBackup`, `sequence` и `legacyMigration`.
4. После транзакции повторно проверяются количество записей и метаданные переноса. Исходный `localStorage` не удаляется.
5. Если база уже содержит данные без подтверждённой миграции, автоматическое объединение блокируется.
6. При ошибке UI сообщает о риске и даёт скачать оригинальный JSON.
7. Второй запуск видит отметку о миграции и не дублирует задания.

Это защищает от частично завершённой транзакции. Полная сквозная проверка каждой пары исходная/восстановленная запись, fault injection на обрыве, штатное восстановление из версионированного архива, SHA-256-манифест и отдельный backup UI входят в **TASK166.2/166.4**, а не выдаются за завершённые.

## Совместимость

- Старый QWBANK v1 до 500 записей переносится без ручного преобразования.
- QWORK v1 остаётся неизменным, включая `task.source.id/number`. Импорт сохраняет внутренний ID, если он свободен; конфликты ID и номеров разрешаются в одной транзакции.
- Редактирование условия, ответа, Markdown-решения, критериев, графика, схемы и иллюстрации остаётся функцией существующего редактора.
- Экспорт до 500 задач — QWBANK v1; для больших коллекций предварительный QWBANK v2 с количеством записей и простой контрольной суммой. **Это не криптографически проверенный backup и не замена резервной копии Windows.**
- Автосохранение в IndexedDB не гарантирует сохранность при очистке профиля браузера/квоты или смене браузера. Пользователь должен экспортировать данные отдельно.

## Windows SQLite

В `main` нет готового нативного Tauri-проекта; полноценной записи Windows-приложения на диск не реализовано. Не создавались фиктивные Rust/SQLite методы. Будущий адаптер должен реализовать тот же асинхронный `BankRepository` на SQLite, хранить базу в `appData`, использовать UNIQUE для `bankNumber`, транзакции и SQLite Backup API. Нативная база и вложения — отдельный TASK166.4.
